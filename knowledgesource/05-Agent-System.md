### ❗ Common Misjudgments

5. **Don't assume `agent_router.py` implements routing** — it is a stub
6. **The system prompt is rebuilt on every `chat_stream()` call**, not cache-stable (memory is hash-cached but paths/usernote change each time)
7. **search_files is hardened (2026-10-15)** — execution path = `asyncio.to_thread` (does not block the event loop) + directory pruning + streaming chunked search (`_stream_search`, 1MB chunks, constant memory, supports arbitrarily large files) + binary double-filter (extension blacklist + NUL byte detection) + 30s time budget + 200-result cap; constants defined at the top of `tool_executor_impl.py` (`_SEARCH_*`). Background: the old implementation did synchronous os.walk + full file reads (measured 32s+ / 3GB / 579MB peak on a single file), now fixed. `find_files` remains the old unpruned implementation (not hardened, lower risk — it only matches file names)
8. **grep/git output decoding fixed (2026-10-15)** — root cause: `subprocess text=True` decoded rg/git's UTF-8 output with cp936 on Chinese Windows; any Chinese in the output → decode error swallowed → `stdout=None` → grep returned "No matches found" (silent false negative). Fix: `_tool_grep`/`_tool_git_status`/`_tool_git_log`/`_tool_git_diff` now pass `encoding='utf-8', errors='replace'`. Note: tasklist/taskkill output is localized GBK and **must not** be switched to UTF-8 (currently correct as-is). Always specify encoding explicitly in new subprocess calls
9. **"Silent stream termination" incident & self-healing (2026-10-15 investigation + fix; 2026-10-16 recurrence + patch)** — symptom: the model silently stops at the "thinking → acting" junction (reasoning finishes but no tool call / no closing text, stream just ends; occasionally `｜｜DSML｜｜` markers leak); the backend's old `if not tool_calls: break` (log: "No tool calls, task completed") misjudged it as completion, invisibly to the user. Historical similar reports (2026-09-12/09-25 "you're stuck") match the same pattern; max_tokens truncation was ruled out. Fix trio: ① log persistence (gateway/log_setup.py → `{PEBBLE_HOME}/logs/backend.log`) ② per-round finish_reason capture + stream-end log (stop/length/None distinguishable) ③ auto-retry once on suspicious end (`_is_suspicious_stream_end`: length truncation or no text output; retry = echo current output + inject continuation prompt; limited to once per turn). Triage entry: search backend.log for "Suspicious stream end" / "stream end: finish_reason=". **2026-10-16 recurrence & patch**: a pure-thinking empty-output case (finish_reason=stop, content_len=0, reasoning_len=12102) exposed a defect in the retry construction — echoing the empty assistant message (content=None, no tool_calls) got rejected by the API with 400 "Invalid assistant message", hard-terminating the turn instead of healing it. Patch (agent_chat_service_v2.py): ① echo the assistant message only when content is non-empty (skip otherwise; the continuation prompt alone keeps the request legal) ② graceful fallback — if a suspicious-retry request is rejected by the API, log a warning and accept the turn as complete (in_suspicious_retry / graceful_abort flags) instead of raising. **Root nature of the phenomenon (for awareness)**: this is an intermittent model-side edge behavior — not a network drop, not a client bug. Evidence: finish_reason=stop together with an intact reasoning stream (12k chars) and zero content means the transport delivered everything the model emitted; the model itself chose to end its turn (EOS) at the thinking→acting boundary, emitting neither body text nor tool calls. It has recurred over time (2026-09-12 / 09-25 / 10-15 / 10-16) and cannot be eliminated client-side; the mitigation strategy is detection + one auto-retry, and (after this patch) clean graceful completion even if the retry is rejected. A related variant leaks `｜｜DSML｜｜` markers (mangled tool-call syntax). Practical expectation: when it happens the turn usually recovers via retry; worst case it now ends cleanly instead of vanishing mid-reply
10. **Agent tool-policy enforcement (added 2026-10-15; chat_agent enabled)** — chat_agent hard whitelist (only read_file/search_files/edit_file/write_file): ① schema layer — `_get_tools_definition(agent_def)` calls `filter_tools_for_agent()`; blocked tools (incl. MCP) are not described to the LLM ② execution layer — `tool_executor_impl.execute()` entry calls `check_agent_tool_policy()` (prevents hallucinated calls / bypass) ③ effective only for enforce=true agents (currently chat_agent only; other agents keep full injection) ④ implemented in agent_loader.py (historical reference implementation base_agent.py.bak is deprecated) ⑤ restart the backend after editing YAML (agent cache is process-level, no mtime invalidation)
11. **Two "orphan" modules are not main-flow components (2026-10-15 graph calibration)** — `query_loop.py` (StatefulQueryLoop, Claude-Code style state machine) and `agent_delegation_streaming.py` (sub-agent event-stream delegation) are **NOT wired into the main flow**: no references anywhere except themselves; the latter also depends on the `agent_router` stub (get_agent always returns None) + `config.get_workspace_directory`, so it is not actually usable. Both are reserve/to-be-wired implementations; when troubleshooting "why doesn't feature X work", first confirm the call chain actually exists
12. **7 tool-infrastructure modules recorded (2026-10-15 graph calibration)** — transcript_manager (42KB transcript archive) / lsp_client (65KB LSP client) / bash_validator (19.5KB six-layer validation) / code_network_guardV2 (three guards) / electron_bridge (HTTP bridge) all have real call chains (see the "Callers" column); earlier graph descriptions were minimal (e.g. "dialog Transcript") — do not underestimate their scale again
