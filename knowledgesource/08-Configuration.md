| tauri.conf.json | Frameless window (1440×900, minWidth 1024 / minHeight 700, decorations:false, dragDropEnabled:false, shadow:true); frontendDist `../dist`, devUrl 5180 with beforeDevCommand `npm run dev` / beforeBuildCommand `npm run build`; **CSP + devCsp** (default-src 'self'; script allows 'unsafe-inline' + 'unsafe-eval' + https:, style allows 'unsafe-inline' + https: — required by the srcdoc preview inheriting the host policy; connect-src allows ws/http 127.0.0.1:19876; img-src adds data: / blob: / http:; devCsp additionally allows the 5180 HMR endpoints); **dangerousDisableAssetCspModification: ["script-src", "style-src"]** — both are required: Tauri's compile-time asset hardening would add a nonce-source and silently void 'unsafe-inline' (CSP3: any nonce/hash in the source list disables it), which kills every inline script the preview injects into srcdoc (html-to-image capture, preview bridge, feedback engine) and every inline style the prototype CSS relies on; bundle resources binaries/*; targets `["nsis"]` (the NSIS installer is what the updater installs) with `createUpdaterArtifacts: true`; shell plugin (open only ^https?://); **updater plugin** — endpoint `https://github.com/5235aa-web/pebbleagent/releases/latest/download/latest.json`, `pubkey` is the minisign public half generated by `tauri signer generate` (the private half lives in `frontend/.tauri-keys/`, gitignored, and must never be committed: the repository is public) | 📦Config |

**Sidecar lifecycle (src/lib.rs)**:
1. setup: find `pebble-backend-x86_64-pc-windows-msvc.exe` in resource_dir → launch with `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP` (stdout/stderr nulled) → set HIGH_PRIORITY_CLASS + IO priority Normal
2. 1 second later boost_all_backends: iterate a Toolhelp32 process snapshot and boost every pebble-backend* process (the Python child spawned by the PyInstaller bootloader) once more
3. RunEvent::Exit: `taskkill /F /T /PID` kills the whole sidecar process tree

**Packaging pipeline**:
1. PyInstaller (root `pebble-backend.spec`, entry run_backend.py) → `dist/pebble-backend.exe` (datas bundle skills / agent_core/agents / config JSONs; binaries carry `vendor/ripgrep/rg.exe` — 4 MB, because the packaged app has no ripgrep on PATH and the grep tool shells out to it; the author's `knowledgesource/` is deliberately excluded — the CKB resolves `knowledgesource/content.md` against the opened project, never the bundle)
2. Copy the artifact to `frontend/src-tauri/binaries/pebble-backend-x86_64-pc-windows-msvc.exe` (Tauri sidecar naming: {name}-{target-triple}.exe)
3. Tauri bundle (`bundle.resources "binaries/*"`, targets `["nsis"]`) → installer + `.sig` from `createUpdaterArtifacts`; frontend build = `npm run build` (vue-tsc && vite build)

> The sidecar filename carries the target-triple suffix for Tauri to recognize it; after backend changes, re-run PyInstaller and copy to binaries/.

**Auto-update (Windows only)**: the feed is a `latest.json` release asset. Installed copies poll `releases/latest/download/latest.json`, compare semver against `tauri.conf.json` `version`, download the NSIS installer, and verify its minisign signature against the pubkey embedded in the config — a re-signed or swapped installer is refused. `npm run release` (`scripts/release.mjs`) signs with `TAURI_SIGNING_PRIVATE_KEY` (falling back to `frontend/.tauri-keys/pebble.key`), runs `tauri build`, then `scripts/publish.mjs` creates the `v{version}` release, uploads the installer, and writes the feed last so a client never reads a feed naming an asset that is not uploaded yet. Recurring manual work is the `version` bump plus a `## {version}` section in `CHANGELOG.md`: `publish.mjs` copies that section into both the GitHub release body and the feed's `notes` field, which is what the in-app update sheet renders, so the page and the app cannot disagree, and `release.mjs` refuses to start when the section is missing — before a build is spent on it. The private key is gitignored and never enters the public repository.

**CI (`.github/workflows/checks.yml`)**: two jobs. `python` runs a 3.11 / 3.14 matrix (compileall → ruff F/E9 → billing scripts → `tests/run_all.py`); `frontend` runs once inside `frontend/` (`npm ci` with `frontend/package-lock.json`, then vue-tsc, then `node tests/run_all.mjs` — the JS runner currently holds no `test_*.mjs` files and passes with zero).
